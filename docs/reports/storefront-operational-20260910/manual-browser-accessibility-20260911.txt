Environment
- Isolated worktree/branch; Django settings_test on 127.0.0.1:8012 and built Nuxt on 127.0.0.1:3112.

- Disposable SQLite data, debug-only OTP, external adapters disabled. One local synthetic order was created; no real message, payment, map request, rollout or production action was made.

Confirmed defects reproduced before correction
1. Activating “Pular para o conteúdo” changed the URL fragment but left focus on AXWebArea.
2. Keyboard activation of “Adicionar” replaced the button with a quantity control and lost the operator's focus context.
3. Escape closed the search visually but left focus in the hidden search field instead of the “Buscar no cardápio” trigger.
4. If both a cart mutation and its reconciliation failed while Django was stopped, the optimistic item remained visible as though accepted.

After correction
- Skip link: Enter moves focus to #main-content.
- Add success: Enter replaces “Adicionar” and focuses “Aumentar <produto>”.
- Search: opening focuses the searchbox; “croissant” exposes the matching product; Escape returns focus to “Buscar no cardápio”; background stays inert while open.
- Partial failure: with Django stopped, the failed optimistic add is removed, the existing cart remains, an error toast is exposed, and focus returns to “Adicionar”. After Django restarts, repeating the same authorized action succeeds and focuses “Aumentar”.
- Checkout: cart context survived the authentication gate; local SMS fallback exposed a debug OTP; the synthetic name was entered once; pickup/time/payment review named 3 items and R$ 41,60 before submit; tracking showed order NB-260911-Z64 as “Pedido recebido” with help, directions, share and cancel actions.
- Second tab: the same browser session opened the account with that in-progress order and observed the cart cleared after checkout.
- Two-tab mutation: simultaneous absolute quantity changes on SQLite produced one 200 and one 409 caused by “database is locked”; after reload both tabs converged to the server quantity 2. This is a laboratory limitation, not PostgreSQL concurrency evidence. The PostgreSQL+Redis gate remains the authoritative concurrency result.
